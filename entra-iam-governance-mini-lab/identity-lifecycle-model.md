# Identity Lifecycle Model

This model describes the identity lifecycle as an organisational and technical process.

## Joiner

A new identity is created when a person or service enters the organisation.

Key questions:

- Who requested the access?
- Which role or business function requires it?
- Which systems are involved?
- Who approves the access?
- Is MFA required from day one?
- Is the access time-limited?

## Mover

An identity changes when a user changes role, department, responsibility or location.

Key questions:

- Which old access rights are no longer needed?
- Which new rights are required?
- Who validates the change?
- Are privileged permissions affected?
- Is there a review after the change?

## Leaver

An identity must be disabled or removed when a user leaves the organisation or a service identity is retired.

Key questions:

- When should access be disabled?
- Which systems depend on the identity?
- Are shared resources transferred to an owner?
- Is there an audit record of the removal?
- Are privileged sessions or tokens revoked?

## Governance principle

Identity lifecycle is not only an IT process. It connects HR, managers, application owners, security, compliance and support.
