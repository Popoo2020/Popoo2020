# Security Policy

## Scope

This GitHub profile contains portfolio projects, educational security labs, governance toolkits and prototype implementations.

The repositories are intended for:

- learning and demonstration,
- recruiter and hiring-manager review,
- responsible AI and cybersecurity portfolio work,
- controlled local testing,
- consulting-readiness examples.

Unless a repository explicitly states otherwise, these projects are **not production systems** and should not be used as-is in a live environment without security review, testing, hardening and adaptation.

## Responsible use

Do not use any security-related repository from this profile against systems, networks, accounts, cloud tenants, applications or users that you do not own or have explicit written permission to test.

Projects with reconnaissance, detection, SOC automation, AI security, red-team planning or incident-triage themes are intentionally designed around safe, defensive, authorised and non-destructive use.

## Reporting security issues

If you identify a vulnerability or unsafe behaviour in one of these repositories, please open a GitHub issue with:

- repository name,
- affected file or workflow,
- description of the issue,
- impact,
- suggested fix if available.

Please do not include real secrets, private customer data or sensitive production details in public issues.

## Secrets and credentials

These repositories should not contain real secrets, API keys, passwords, tokens, private certificates or production configuration.

If a secret is accidentally committed, it should be considered compromised and rotated immediately.

## AI safety and governance notes

AI-related repositories in this profile use conservative language, safe fallbacks and human-review assumptions where relevant. They are not legal advice, certification evidence, medical advice or complete production security controls unless explicitly stated.

For real-world use, organisations should perform environment-specific review covering:

- data protection and privacy,
- supplier/tool due diligence,
- threat modelling,
- human oversight,
- logging and monitoring,
- incident response,
- access control,
- regulatory and contractual obligations.
