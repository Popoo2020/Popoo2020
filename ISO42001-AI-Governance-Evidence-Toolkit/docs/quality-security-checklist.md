# Quality and Security Checklist

## Quality gates

Before presenting this toolkit to an employer, client or collaborator, confirm:

- [ ] Unit tests pass.
- [ ] CI passes on the latest pull request or main branch.
- [ ] The readiness report generates successfully.
- [ ] Sample data is clearly fictional or anonymised.
- [ ] Limitations are visible in the README.
- [ ] The case study is clearly labelled as simulated/anonymised.
- [ ] Links and file references in the README work.

## Security gates

- [ ] No real secrets, tokens or credentials are committed.
- [ ] No real client records or personal data are committed.
- [ ] Supplier review templates avoid unsupported claims.
- [ ] Human oversight requirements are documented for high-risk examples.
- [ ] Incident and complaint handling is represented as a template, not a production process.
- [ ] The project avoids claiming certification, audit approval or legal advice.

## Portfolio presentation gates

- [ ] Architecture document is present.
- [ ] Threat model is present.
- [ ] Demo output is present.
- [ ] Version notes are present.
- [ ] README explains what the project demonstrates for AI Governance and Cybersecurity GRC roles.

## Recommended review cadence

Review this checklist whenever:

- a new governance artefact is added,
- sample data changes,
- the report generator changes,
- the project is shared in a job application,
- the project is used as a basis for a real consulting discussion.
