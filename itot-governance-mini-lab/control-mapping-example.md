# Control Mapping Example

This file shows how a governance requirement can be translated into practical documentation and evidence.

## Example control area: Access management

| Requirement area | Practical interpretation | Example evidence |
|---|---|---|
| Access is granted based on role and need | Users should only receive access that supports their job function | Role matrix, approval records, access review notes |
| Privileged access is limited and documented | Administrative access should be named, approved and periodically reviewed | Privileged account list, approval log, review checklist |
| Remote access is controlled | Remote access should be approved, logged and limited to defined purposes | Remote access procedure, VPN/MFA settings evidence, session logs |
| Changes are traceable | Changes to sensitive systems should have a documented reason and owner | Change record, maintenance log, responsible owner |

## Example evidence checklist

- Asset owner identified
- Access owner identified
- Role or business need documented
- Approval process described
- Logging expectation defined
- Review frequency defined
- Exception process described

## Notes

The purpose of this example is to demonstrate structured thinking. It can be adapted to different frameworks and organisational requirements.
